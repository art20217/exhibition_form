# 訪客資料登記表 — Offline Prototype

展覽客戶資料蒐集表單，單一 HTML 檔案，完全離線運作，零伺服器依賴。

---

## Demo

GitHub Pages：`https://art20217.github.io/exhibition_form/`

直接在平板或手機瀏覽器開啟即可使用，不需安裝任何應用程式。

## v3.4 更新重點

**單一展覽的表單，變成可以重複用在每一場展覽的工具。**

- **活動首頁成為根畫面：** 開啟後先看到活動列表，分「使用中」與「已結束」兩區，每張卡片顯示活動名稱、日期區間、接待人員數與紀錄筆數。點進去才是該活動的表單。
- **新增／編輯／結束／刪除活動需要 PIN：** 展場平板放在客戶面前，管理按鈕預設隱藏，點右上角齒輪輸入 PIN 後才會出現。新增活動可設定活動名稱、活動日期區間、接待人員名單（英文＋中文兩欄），並選擇表單欄位來源——**內建預設**或**複製自某個既有活動**（複製的是獨立副本，日後修改互不影響）。
- **每場活動的欄位與資料完全獨立：** 欄位定義以 `<活動 id>::<欄位群組>` 為鍵分別儲存，每筆紀錄帶 `eventId`。後台的欄位設定、資料紀錄、匯出、「清除全部紀錄」一律只作用於目前開啟的活動。
- **填單人員與填單日期改在活動頁選擇：** 進入活動後，業務先選自己的名字（**可複選兩人以上**）與填單日期，才能點開兩個表單入口；**沒選就進不去**。填完自動帶入該筆紀錄，並在頁面上方持續顯示「填單人員：… ｜ 填單日期：…」與「重新選擇」，同一位業務連續接待時不必重選，換人時一眼看得出要改。
- **接待人員改為複選、由活動供應：** `greeter` 由單選改為多選，選項不再於後台編輯，改由活動的接待人員名單提供；`visit_date` 同樣改由活動頁帶入。兩個欄位定義仍保留（所以資料紀錄的「接待人員」欄與匯出欄位都還在），在後台標示為**由活動設定**、不可編輯或刪除。
- **業務備註頁只在還有業務專屬欄位時出現：** 上述兩欄搬走後，預設情況下業務備註頁已無內容，交接畫面直接顯示「完成，返回」。若在後台為該群組新增自訂欄位，業務入口會自動回來。
- **已結束的活動：** 兩個表單入口停用，但仍可進入後台檢視與匯出資料。結束／重新啟用是可復原的動作，只需一層確認；刪除活動仍是兩層＋輸入 `DELETE`。
- **匯出加上 Event 欄、檔名帶活動名稱：** `export_<活動名稱>_YYYYMMDD_HHMMSS.zip`。
- **系統設定維持全域：** 裝置名稱、管理者 PIN、GDPR 條文適用於所有活動。

### 資料相容性（v2 → v3 → v3.1 → v3.2 → v3.3 → v3.4 逐步自動遷移）

舊版資料庫會在開啟時自動遷移，已蒐集的紀錄不受影響：

- 「洽談事由（inquiry_type）」欄位定義自動從客戶欄位移至需求欄位；舊紀錄中存在客戶資料下的值仍可正常顯示與匯出。
- 「潛力評級（potential）」欄位定義自動從星級（或更早的 A/B/C 下拉選單）改為七級單選；舊紀錄既有的星數或字母值照原樣顯示，不做數值轉換。
- 接待人員／訪談日期／訪客國籍／語言四個欄位會自動加到 Staff Fields 最前面；若 Product of Interest 欄位仍是從未編輯過的空白預設值，會自動填入完整機型分類選項——**已自訂過的選項或其他業務欄位不會被覆蓋**。
- 新增 `companyFields` 資料表與預設欄位，既有紀錄的 Company Profile 資料視為空白，可事後從後台 Records 編輯補齊。
- 舊紀錄的語言標記（Language）保留於匯出資料中；新紀錄該欄為空白。
- **v3.2：** 「使用機器（machines_used）」欄位若尚未設定 `perGroupOther`，會自動補上（並新增「本土」空白分類），**既有的品牌選項清單完全保留、不被覆蓋**。「接待人員（greeter）」若尚未允許「其他」，會自動補上（既有三個姓名選項不變）。「訪談日期（visit_date）」若仍是舊版單選按鈕組，會自動轉為新的 `date` 欄位類型；舊紀錄中已存的日期字串（如 `08/06`）維持原樣顯示，不做格式轉換。
- **v3.3：** 訪客國籍／語言自動移入客戶資料欄位，感興趣產品／成交機率／備註自動移入客戶需求欄位（依此順序），業務備註欄位只留下接待人員與訪談日期；「潛力評級」更名為「成交機率」（欄位 id 不變）。**搬移時沿用欄位原有的定義，後台自訂過的標籤與選項完全保留。** 此遷移由 `config` 中的 `migratedTo33` 旗標控制、只執行一次——因此日後在後台自行刪除這些欄位，不會在下次開啟時被重新加回。舊紀錄的值仍留在原本的 `staffFields` 中，讀取時會自動向前回溯，Records 與匯出照常顯示。
- **v3.4：** IndexedDB 由 v1 升到 v2，新增 `events` 資料表。開啟時若尚無任何活動，會先跑完上述整條遷移鏈，再把結果收編進一個預設活動：
  - 有既有紀錄時活動命名為「2026 美國展」（可在活動列表改名），日期區間自動取既有紀錄的最早與最晚日期；全新安裝則建立名為「新活動」、起訖為當天的活動。因此**開機後一定至少有一個活動可以進入**，不會因為「新增活動需要 PIN」而卡在空白首頁。
  - 活動的接待人員名單取自舊的 `greeter` 選項，**後台自訂過的姓名一併沿用**。
  - 四組欄位定義從無前綴的鍵搬到 `<活動 id>::<群組>`，舊鍵刪除；每筆既有紀錄補上 `eventId`。
  - `greeter` 轉為 `checkbox-group` 並標記 `source: 'event'`，`visit_date` 同樣標記。**舊紀錄中以字串儲存的單一接待人員原樣保留、不強制轉成陣列**——列表、編輯與匯出三處都同時支援字串與陣列。
  - 判斷依據是「`events` 是否為空」而非旗標，因此重新載入不會重複建立活動。

## 功能總覽

### 表單模式（Exhibition Mode）

面向展覽現場的客戶與業務人員，流程如下：

```
活動首頁（使用中 / 已結束 的活動列表）
  → 點進某一場活動
  → 活動頁：選填單人員（可複選）+ 填單日期 → 兩個表單入口才會開放
  → 填寫第一步：先選的表單（送出即建檔，並帶入填單人員與日期）
  → 自動接續第二步：Company Profile 公司背景資料（固定居中）
  → 自動接續第三步：後選的表單
  → 交接畫面（感謝頁 + 請交還平板）
  → 回到活動頁（填單人員與日期仍保留），等待下一位
```

> 若後台在「業務備註欄位」中另外新增了業務專屬欄位，交接畫面會多出「Staff 工作人員 →」入口，進入業務頁填寫後再回到活動頁。預設情況下沒有這類欄位，交接畫面直接顯示「完成，返回」。

- **中英雙語排版：** 所有客戶面文案固定雙語呈現，英文為主、中文為副，無需切換。
- **動態表單欄位：** 依後台配置動態渲染，支援 text / email / tel（含國碼選單）/ select / checkbox-group（多選，可分類子區塊）/ radio-group（單選按鈕組，可長文字）/ textarea / rating（星級，供後台自訂欄位使用）/ date（原生日期選擇器，空白預設當天）。checkbox-group 與 radio-group 皆可開啟「其他，請填寫」；checkbox-group 另可開啟「每個分組獨立其他」，讓每個分類子區塊各自擁有獨立的「其他」欄位（如「使用機器」的歐洲／台灣／大陸／韓國／本土）。短標籤選項按鈕採固定寬度整齊排列，長文字說明選項維持全寬。
- **輸入驗證：** 必填欄位檢查、Email 格式檢查，雙語錯誤提示顯示在欄位下方。
- **GDPR 同意聲明：** 於客戶資料表單底部（不論填寫順序），中英文聲明同時顯示，未勾選不可送出。聲明文字可在後台自訂。
- **中途放棄保留：** 每一步表單送出即寫入 IndexedDB，客戶中途離開也不會遺失已填資料，業務可事後從後台補齊。
- **名片拍照存檔：** 客戶資料填寫頁頁尾內嵌拍攝按鈕，照片經 Canvas API 壓縮（長邊 ≤1600px，JPEG 品質 0.8）存入 IndexedDB，支援預覽、重拍、移除（移除需兩層確認）。

### 活動管理（Event Management）

活動首頁是開啟後的第一個畫面，列出所有活動並分為「使用中」與「已結束」兩區。

- **一般狀態下只能點選活動進入**，看不到任何管理按鈕——避免展場平板被誤觸。
- 點右上角齒輪 → 輸入 PIN → 進入管理模式，出現「＋ 新增活動」與每張卡片的 編輯／結束活動（或重新啟用）／刪除。點頁首的「🔓 管理中」可隨時鎖回；離開活動首頁也會自動鎖回。
- **新增／編輯活動**可設定：活動名稱、開始與結束日期、接待人員名單（每列英文＋中文；英文是匯出與紀錄實際儲存的值，中文只用於畫面顯示）。新增時另可選擇表單欄位來源：**內建預設欄位**，或**複製自**某個既有活動。
- **結束活動**只需一層確認（可隨時重新啟用）；**刪除活動**需兩層確認並輸入 `DELETE`，會連同該活動的所有紀錄、名片照片與欄位設定一併刪除。

### 後台管理模式（Admin Panel）

進入某個活動後，透過活動頁右上角齒輪圖示 → 輸入 4 位 PIN 碼進入（預設 `0000`）。後台介面為純中文，**所有內容都只作用於目前開啟的活動**（頁首會顯示活動名稱）。

分為六個頁籤：

**客戶資料欄位** — 管理客戶資料表單欄位。預設六個核心欄位（姓名／公司／電子信箱／電話／訪客國籍／語言）不可刪除但可編輯。

**客戶需求欄位** — 管理客戶需求表單欄位。預設四個欄位：洽談事由／感興趣產品／成交機率／備註。

**公司背景欄位** — 管理公司背景資料表單欄位。預設十個欄位（行業別、客戶類型、公司型態、公司產品×2、使用機器、股份型態、營業額、員工人數、產能、規模型態）。「使用機器」預設開啟「每個分組獨立其他」，歐洲／台灣／大陸／韓國／本土五個分類子區塊各自可填寫其他品牌。

**業務備註欄位** — 管理業務備註欄位。預設的接待人員與訪談日期兩欄標示為**由活動設定**，內容改由活動頁的填單人員／填單日期帶入，在此不可編輯或刪除（要改接待人員名單請到活動列表編輯該活動）。此頁籤可自行新增其他業務專屬欄位；只要存在這類欄位，交接畫面就會出現業務入口。

四個欄位頁籤皆支援新增、編輯、刪除，以及**按住把手拖曳排序**。每個欄位可設定中英名稱、類型、是否必填、是否允許「其他」、選項列表（可設定分類，用於分區塊顯示）；checkbox-group 欄位勾選「允許其他」後，可再勾選「每個分組獨立其他」並填入「額外空白分類」（逗號分隔），讓沒有預設選項的分類子區塊也能顯示（僅供自由填寫）。

**資料紀錄** — 檢視本活動已蒐集的紀錄（其他活動的紀錄不會出現在這裡，「清除全部」也只清本活動）。平板以表格呈現（星級以 ★ 顯示），手機自動切換為卡片式排版。顯示蒐集統計（筆數、含名片照片筆數）。支援逐筆編輯（「編輯」開啟客戶資料＋需求＋公司背景合併編輯表單，含名片照片）、逐筆刪除（兩層確認）、檢視名片照片（點擊 📷 圖示放大）。

**系統設定** — 設定裝置名稱（附加在每筆紀錄上，多台平板時用於辨識來源）、修改管理者 PIN 碼、編輯 GDPR 同意聲明中英文。**此頁籤是全域設定，適用於所有活動**（其餘頁籤皆為單一活動範圍）。

### 資料匯出

後台「資料紀錄」頁籤點擊「匯出資料」，瀏覽器端打包並下載一個 ZIP 檔案：

匯出範圍是**目前開啟的活動**，檔名帶活動名稱：

```
export_2026_美國展_YYYYMMDD_HHMMSS.zip
├── records.xlsx
└── cards/
    ├── 001_CompanyName_ContactName.jpg
    ├── 002_CompanyName_ContactName.jpg
    └── ...
```

- **records.xlsx** 包含兩個工作表：「Records」（本活動的所有紀錄，前置欄位為 ID／Timestamp／Device／**Event**／Language，其後依客戶資料 → 客戶需求 → 公司背景 → 業務備註排序（欄名沿用欄位的英文名稱，供下游處理使用），「其他」選項存為 `Other: <填寫內容>`，複選的接待人員以 `; ` 串接，電話欄位格式化為文字避免 Excel 吃掉開頭符號）與「Field Definitions」（當前欄位定義與所屬分類 Customer / Needs / Company / Staff，供接手人員理解資料結構）。
- **cards/** 資料夾包含所有名片照片，檔名與 XLSX 中的 Card Photo Filename 欄位對應。無照片的紀錄不產生檔案。

### 資料刪除與確認

所有刪除作業都需要**兩層確認**才會執行，防止現場誤觸：第 1 層說明即將刪除的內容，第 2 層再次確認此動作無法復原。適用於單筆欄位刪除、單筆紀錄刪除、移除名片照片、**刪除活動**，以及後台「資料紀錄」頁籤的「清除本活動全部紀錄」（後兩者另需先輸入 `DELETE` 才能進入第 2 層）。

可復原的動作不套用兩層確認：**結束活動／重新啟用活動**只跳一層確認，因為它不刪除任何資料、隨時可以改回來。

所有浮動視窗（PIN 對話框、欄位編輯器、活動編輯器、刪除確認、名片燈箱）都鎖住遮罩，點視窗外不會關閉，只能用視窗內的按鈕關閉。

## 使用指南

### 展前準備

1. 用平板瀏覽器開啟表單網址（或直接開啟 `index.html` 檔案），畫面停在活動首頁。
2. 點擊右上角齒輪圖示，輸入 PIN `0000` 解鎖活動管理。
3. 點「＋ 新增活動」建立這次的展覽：填活動名稱（如 `2026 美國展`）、活動起訖日期、這次參展的接待人員（英文＋中文）。**表單欄位來源**選「內建預設欄位」，或選「複製自」上一場展覽以沿用已調整好的選項。
4. 點進剛建立的活動，再點右上角齒輪輸入 PIN 進入後台。
5. 進入 **系統設定**：修改裝置名稱（如 `Tablet-A`）、修改 PIN 碼、修改 GDPR 聲明文字（替換為公司名稱）。此頁為全域設定，每台平板只需設定一次。
6. 進入 **客戶資料欄位** / **客戶需求欄位** / **公司背景欄位** / **業務備註欄位**：依這次展覽的需求調整欄位和選項，按住把手拖曳調整順序。例如在「感興趣產品」中新增產品線名稱。這些設定只影響這一場活動。
7. 點擊「← 返回表單」回到活動頁。
8. 如有多台平板，每台重複上述步驟，確保裝置名稱不同。

### 展覽現場操作

1. 在活動首頁點進這次的展覽。
2. 業務先在活動頁點選**自己的名字**（兩人以上一起接待就複選）與**填單日期**，兩者都選好後兩個表單入口才會亮起。
3. 客戶到訪時，依情境選擇先填「客戶資料」或先填「客戶需求」（可由客戶自填或業務協助輸入）。
4. 第一步填完按「Next 下一步」，接續第二步「Company Profile 公司背景資料」，再接續第三步（後選的表單），皆按「Next 下一步」，最後一步按「Finish 完成」。（訪客國籍／語言在客戶資料頁填寫；感興趣產品／成交機率／備註在客戶需求頁填寫；名片拍照在客戶資料頁尾。）
5. 交接畫面出現後請客戶將平板交還，業務點右下角「完成，返回」回到活動頁。填單人員與日期已自動寫入這筆紀錄。
6. 回到活動頁後上方會顯示目前的填單人員與日期，同一位業務可直接接待下一位客戶；**換人時記得點「重新選擇」改成自己的名字**。

### 展後匯出

1. 進入該活動 → 後台 → 資料紀錄 頁籤。
2. 點擊「匯出資料」，等待 ZIP 檔案下載完成（只會匯出這一場活動的資料）。
3. 解壓後用 Excel 開啟 `records.xlsx`，照片在 `cards/` 資料夾中。
4. 匯出確認無誤後，回到活動首頁把這場活動設為「結束活動」——資料仍保留、隨時可以再匯出，但表單入口會停用，避免之後誤填到舊活動。若確定不再需要平板上的資料，可執行「清除本活動全部紀錄」或直接刪除該活動。

## 技術架構

| 項目 | 說明 |
|---|---|
| 檔案結構 | 單一 `index.html`，內含所有 CSS / JS / 函式庫，原始碼直接可讀可改 |
| 前端框架 | React 18.3.1 UMD（內嵌）+ DC 模板引擎（dc-runtime，內嵌） |
| 資料儲存 | IndexedDB v2（四個 Object Store：`config`、`events`、`records`、`fieldDefinitions`）。`fieldDefinitions` 以 `<活動 id>::<群組>` 為鍵，每場活動各有 customerFields / needsFields / companyFields / staffFields 四組定義；每筆 `records` 帶 `eventId`；`config` 為全域設定（PIN、裝置名稱、GDPR 條文、遷移旗標） |
| 照片處理 | Canvas API 壓縮後以 Base64 存入 IndexedDB |
| 匯出 | 內建 XLSX 生成 + ZIP 打包（ExportLib，inline 於 HTML 中） |
| 拖曳排序 | Pointer Events 自製實作（相容 iPad Safari 觸控，不依賴 HTML5 Drag & Drop） |
| 螢幕適配 | 響應式 CSS，`@media (max-width: 768px)` 斷點，支援 `safe-area-inset` 與 `100dvh` |
| 離線能力 | 完全離線，所有依賴皆已內嵌，不需任何網路連線 |
| 瀏覽器相容 | iPad Safari 16+、Chrome Android 100+、主流手機瀏覽器 |

### 修改指南

`index.html` 結構由上而下：App 樣式 → React / ReactDOM UMD → dc-runtime → ExportLib → `x-dc` 模板（畫面標記）→ `text/x-dc` 邏輯腳本（`Component` 類別）。日常修改只需動最後兩段。注意事項：

- 模板內具嚴格 HTML 解析規則的元素以 `sc-raw-` 前綴書寫（`sc-raw-select`、`sc-raw-table`、`sc-raw-tr` 等），瀏覽器解析時才能保留其中的 `sc-for` / `sc-if` 子節點，dc-runtime 會在渲染時還原。
- 真正的 `<x-dc>` 模板元素之前，檔案中不可出現字面上的 x-dc 開頭標籤序列（dc-runtime 以第一個出現位置定位模板）。
- 選項的 `en` 是**紀錄實際儲存的值**，`zh` 只用於顯示。要改 `en` 就必須同步改寫已蒐集紀錄中的值（見 `loadAllData` 中的 `VALUE_RENAMES`），否則舊答案會對不上選項；只改中文標籤則用 `labelFixes`，以「原值」比對，後台已自訂過的標籤不會被覆蓋。
- `state` 的 `customerFields` / `needsFields` / `companyFields` / `staffFields` 永遠是**目前開啟活動**的定義，所以表單、後台、匯出等讀取端不需要知道活動的存在；只有存取 IndexedDB 的那一層（`saveEventDefs` / `loadEventDefs` / `defKey`）需要帶活動前綴。
- 欄位若標記 `source: 'event'`（接待人員、訪談日期），代表其內容由活動頁供應：不在業務備註頁渲染、後台不可編輯或刪除，但定義仍在，資料紀錄欄位與匯出欄位因此保持完整。

### 已知限制

- **不具備雲端同步。** 多台平板的資料需各自匯出後手動合併。
- **照片儲存佔用 IndexedDB 空間。** 壓縮後單張約 200～500KB，100 筆含照片約 20～50MB。iPad Safari 的 IndexedDB 配額通常足夠，但建議展後及時匯出並清除。
- **瀏覽器清除資料會遺失所有紀錄。** 確保平板已啟用螢幕鎖定密碼，避免他人誤操作。
- **不含 OCR 名片辨識。** 名片照片僅作為存檔，不自動擷取文字。
- **PIN 碼僅防止誤觸，不構成安全機制。** 活動管理與後台共用同一組 PIN；交接畫面的「Staff」按鈕未設密碼，僅以視覺弱化降低誤觸。
- **填單人員靠業務自行選擇，系統不驗證身分。** 換人接待時若忘了點「重新選擇」，紀錄會掛在上一位業務名下——活動頁上方的常駐橫幅就是為了讓這件事一眼看得出來。
- **活動之間的欄位設定不會同步。** 複製活動是一次性的深拷貝；建立之後修改任一方都不影響另一方。

## 後續升級建議

此原型驗證了核心流程的可行性。以下是正式版建議的升級方向，按優先順序排列：

### Phase 1：PWA 化（Offline-First + Cloud Sync）

- 加入 Service Worker 實現正式的離線快取，使用者首次透過網路開啟後，即使完全離線也能正常使用。
- 實作背景同步（Background Sync API）：資料先寫入本機 IndexedDB，偵測到網路後自動同步至後端伺服器。
- 現場搭配 4G/5G 行動分享器作為主要網路來源。

### Phase 2：後端服務

- 照片上傳至物件儲存服務（如 AWS S3 / Azure Blob），資料庫僅存 URL。
- 多台平板的資料透過雲端自動合併，不需手動匯出。
- 匯出由伺服器端打包，不受瀏覽器記憶體限制。
- 展後自動寄送跟進信件（避免現場即時寄信，改為批次處理並正確設定 SPF/DKIM）。

### Phase 3：安全性與合規

- 實作 Web Crypto API 加密 IndexedDB 中的客戶資料。
- 使用者帳號與權限管理（區分管理員與一般業務）。
- GDPR 同意聲明文字由法務審定。
- 資料保留期限與自動清除策略。

### 可評估的功能擴展：名片 OCR 辨識

目前名片拍照僅存檔，不做文字辨識。如有需求，可在後端服務建立後加入 OCR 功能（如 Google Cloud Vision API），拍照後自動擷取姓名、公司、Email、電話等欄位並預填至表單，減少手動輸入。此功能依賴雲端 API 呼叫，不適合在純離線架構下實作，建議在 Phase 2 完成後再評估投入產出比。

### 技術債與改善項目

- XLSX 與 ZIP 生成邏輯為自行實作（ExportLib）。正式版不再受單一檔案體積限制，建議改用 SheetJS（xlsx）與 JSZip 等成熟函式庫，可獲得更完整的 Excel 格式支援（欄寬自動適應、凍結窗格、儲存格樣式等）與更可靠的跨瀏覽器相容性。
- 後台的欄位管理與 Settings 頁籤尚未做完整手機適配（Records 頁籤已有卡片式手機排版），如需在手機上管理後台設定需額外處理。
- 國碼選單目前為硬編碼列表，正式版可改為完整的國際電話國碼資料庫。
- 考慮加入裝置層級的安全提醒（iPad 引導式取用模式設定指引）。
